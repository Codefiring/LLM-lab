# **1. Graph Edit Distance 方法介绍**

## **1.1 定义**

**Graph Edit Distance（GED）** 是度量两个图之间“不相似程度”最经典和严谨的图论方法之一。
它通过最小化以下图编辑操作的成本，来衡量将一个图转化为另一个图所需的最小代价：

### **允许的编辑操作**

1. **节点插入（Node Insertion）**
2. **节点删除（Node Deletion）**
3. **节点替换（Node Substitution / Label Mismatch）**
4. **边插入（Edge Insertion）**
5. **边删除（Edge Deletion）**
6. **边替换（Edge Label Substitution）**

每个操作都有一个代价（cost），GED 就是：

[
GED(G_1, G_2) = \min \sum cost(edit_ops)
]

GED 越小，两个图越相似。

---

## **1.2 为什么 GED 特别适合评估 ioctl 状态机？**

NPU 状态机来自 **bitmask 状态** + **ioctl 转移**，自动抽取（ASDG 结果）可能产生：

* **缺失某个状态 → node missing**
* **合并/分裂状态 → node substitution**
* **漏掉某条 ioctl → edge deletion**
* **误检测出一条 ioctl → edge insertion**
* **把 ioctl 从 A→B 错判为 A→C → edge substitution**

这些都天然对应 GED 的原子编辑操作，因此：

➡ **GED 可以把“状态机抽取偏差”变成可量化、可解释的数值。**
➡ 你可以通过每种操作的 cost 设置权重（例如漏掉状态比漏掉边更严重）。

# **2. 基于 NPU 状态机的评估方案设计（具体示例）**

我们使用你前面已经构建的：

* **FSM_GT（Ground Truth）**
* **FSM_PRED（Predicted / Autogenerated）**

作为示例，让你能直接验证 GED 评估是否符合预期。

---

## **2.1 需要比较的两张图**

### **Ground Truth FSM（这里简化为核心转移）**

* POWER → GRAPH   （T5）
* GRAPH → STREAMON （需先 FORMAT，但抽象机 1 中是单层抽象）

### **Predicted FSM 的偏差**

1. 漏掉了：
   **(POWER → GRAPH)** → *False Negative*
2. 多出了一条不存在的：
   **(GRAPH → STREAMON)** → *False Positive*

这样刚好形成了典型编辑操作，非常适合作为你的评估示例。

---

## **2.2 将差异映射到 GED 编辑操作**

我们比较边集合：

| GT Edge          | Pred Edge | 说明 | GED 操作             |
| ---------------- | --------- | -- | ------------------ |
| POWER → GRAPH    | ❌         | 缺失 | **Edge deletion**  |
| GRAPH → STREAMON | GT 中不存在   | 多出 | **Edge insertion** |

没有新增/删除节点，因此节点部分不涉及 edit cost。

---

## **2.3 设置 GED 操作代价（可调权重）**

你可以根据 fuzzing 中的实际影响设置代价。例如：

| 编辑操作                      | 解释                   | cost |
| ------------------------- | -------------------- | ---- |
| Node insertion / deletion | 抽取模型错识别状态，影响极大       | 5    |
| Edge insertion            | 误报：让 fuzzer 认为某路径存在  | 1    |
| Edge deletion             | 漏报：阻止 fuzzer 走某些真实路径 | 2    |
| Edge substitution         | 转移错误方向               | 2    |

为什么 edge deletion 代价 > edge insertion？
因为漏掉合法路径，可能导致 fuzz 无法覆盖到某个 ioctl 链 → 对测试影响更大。

你也可以调成：

* 全部 cost = 1（简单比较）
* 或根据 Ioctl 类型分类加权（更精细的指标）

---

## **2.4 示例计算 GED（根据代价表）**

| 偏差类型                     | 代价 |
| ------------------------ | -- |
| 删除 GT 中的 (POWER → GRAPH) | 2  |
| 插入错误的 (GRAPH → STREAMON) | 1  |

∴ 最小编辑成本为：

[
GED(FSM_{GT}, FSM_{PRED}) = 2 + 1 = 3
]

你可以进一步归一化：

[
Sim = 1 - \frac{GED}{MaxCost}
]

MaxCost 可设为：

[
|E_{GT}| + |E_{PRED}|
]

例如 GT 有 13 条边，PRED 有 13 条：

[
MaxCost = 26 \quad(\text{若每个边 edit cost = 1})
]

则：

[
Sim = 1 - 3/26 = 0.8846
]

**即：预测状态机与 GT 的相似度为 88.5%**

# **3. GED 评估方案能测什么？能反映什么内容？**

这是最关键部分，用于你写论文/设计评估框架。

---

## **3.1 能评估的维度**

| 评估维度             | 能否评估？ | GED 体现方式                                 |
| ---------------- | ----- | ---------------------------------------- |
| 状态识别是否正确         | ✔     | node insertion / deletion / substitution |
| ioctl 转移是否完整（FN） | ✔     | edge deletion                            |
| 是否误判出不存在的转移（FP）  | ✔     | edge insertion                           |
| 转移方向是否正确         | ✔     | edge substitution                        |
| 是否错误合并两个状态       | ✔     | node deletion + edge rewiring            |
| 是否错误分裂状态         | ✔     | node insertion + edge redistributions    |
| 状态机总体结构是否被破坏     | ✔     | GED 数值大小整体反映                             |

可见 GED 能从**结构层面**全面测量“状态机抽取质量”。

---

## **3.2 GED 的数值含义（解释性强）**

数值越小 → 越接近 Ground Truth

你可以描述：

* **GED = 0**：预测状态机完全正确
* **0 < GED ≤ 3**：轻微偏差，只影响少量转移
* **GED > 10**：模型有严重抽取错误
* **GED ≥ 20**：可能状态被合并/分裂，结构性错误

这种解释更符合实验论文写法。

---

## **3.3 GED 结果能反映什么？**

### **(1) 可解释的错误定位**

通过编辑序列，能直接指出：

* 哪个状态被漏掉了（node deletion）
* 哪个 ioctl 转移漏掉了（edge deletion）
* 哪些转移是假阳性（edge insertion）
* 哪些转移方向被识别错误（edge substitution）

你甚至能自动生成：

➡ “ASDG 预测遗漏了 1 条真实转移：POWER→GRAPH”
➡ “ASDG 错误增加了 1 条不存在的转移：GRAPH→STREAMON”

对调试模型很有用。

---

### **(2) Fuzzer-friendly 的意义解释**

* 误插入边（FP）→ 可能让 fuzz 探索无意义路径
* 漏掉边（FN）→ 会阻止 fuzz 走到某些 ioctl 序列（严重）
* 错识别状态（node-level error）→ 会导致状态约束判断错误（非常严重）

所以 GED 本质上能衡量：

**自动抽取能力对正确 fuzzing path 的保持程度**

---

### **(3) GED + 权重机制 可以刻画“关键错误”的影响**

你可以定义：

* format / streamon 类转移权重大（因为对驱动使用路径关键）
* version / query 类 ioctl 权重低（无状态）

这样 GED 不只比较结构，而是比较：

**预测状态机对关键路径的保持程度**

更符合驱动 fuzzing 的实际需求。

利用 **Graph Edit Distance（GED）** 可以构建一个：

### **✔ 可量化**：给出相似度数值

### **✔ 可解释**：指出少了哪些边、多了哪些边

### **✔ 可扩展**：通过权重强调关键路径

### **✔ 与 fuzzing 强相关**：直接反映对合法 ioctl 顺序建模的准确性

最终，它能评价：

1. 状态抽象是否正确
2. ioctl 转移是否完整
3. 预测状态机与真实状态机的结构差异
