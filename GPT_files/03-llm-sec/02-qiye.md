# 一、阿里系（ToB + 合规优先）LLM 上线安全流程

> 关键词：**门禁化、安全一票否决、场景责任制**

## 1️⃣ 组织结构（你在企业里很可能也是这个形态）

* 模型团队（LLM / 多模态）
* 产品团队（业务 owner）
* **安全评估团队（独立）**
* 合规 / 法务（强绑定）

安全评估**不归模型团队管**，这是第一个关键点。

---

## 2️⃣ 上线前强制流程（不可跳过）

### 阶段 A：静态能力 & 基线评估（Gate 0）

必跑项：

* 安全 benchmark（内部版 SafetyBench）
* 历史回归集（Regression Set）
* 敏感话题覆盖率

👉 **不看“效果好不好”，只看“有没有退步”**

> ⚠️ 安全指标回退 = 直接卡死

---

### 阶段 B：自动红队（Gate 1）

核心目标：

> **不是“测全”，而是“测穿”**

* Prompt Injection 模板库
* 多轮诱导
* Role-play 越狱
* 指令覆盖攻击（覆盖 system / developer prompt）

特征：

* **失败样本会被人工逐条看**
* 不接受“模型偶然失误”这种解释

![Image](https://www.paloaltonetworks.com/content/dam/pan/en_US/images/cyberpedia/what-is-a-prompt-injection-attack/Prompt-injection-attack-2025_16.png?imwidth=480)

---

### 阶段 C：业务场景专项（Gate 2，最重要）

阿里最典型的一点：**安全责任跟业务强绑定**

比如：

* 金融 → 投资建议
* 企业 → 内部数据、权限
* 政务 → 政策解读、立场

做法：

* **真实业务 prompt**
* **攻击变体（10~50 个 / 场景）**
* 明确写清楚：
  👉「**这个场景允许失败吗？**」

> 有些场景是：
> **“宁可拒答，也不能错答”**

---

### 阶段 D：人工安全 Review（Gate 3）

这是外部最容易忽略的：

* 安全专家逐条 review 高风险失败样本
* 给结论：

  * 必修（block）
  * 可控（accept risk）
  * 可延后（post-fix）

📌 **安全团队有“一票否决权”**

---

## 3️⃣ 阿里系的核心特征（一句话）

> **“上线是合规行为，不是技术行为。”**

# 二、字节系（内容安全 + 对抗优先）流程

> 关键词：**规模化红队、内容风险、数据驱动**

## 1️⃣ 字节最不一样的地方

字节内部默认假设：

> **“用户一定会恶意使用”**

所以流程更偏向：

* **内容攻击**
* **规模化失败统计**
* **对抗样本生成**

---

## 2️⃣ 上线前流程拆解

### 阶段 A：大规模 Prompt Fuzzing

* Prompt 变体自动生成
* 同一意图 100~1000 种说法
* 多语言混合
* 表情 / 拼写 / 拆词

目的不是“发现漏洞”，而是：

> **统计失败概率分布**

---

### 阶段 B：LLM-as-Judge + 人工抽检

* Judge 打标 SAFE / RISK / FAIL
* 人工只看 FAIL 和边界样本

📌 字节非常在意：

* **失败是否“可复现”**
* **是否容易被普通用户触发**

---

### 阶段 C：内容域专项（强制）

例如：

* 暴力
* 仇恨
* 未成年人
* 灰色违法

这些是：

> **不看业务价值，只看风险**

---

### 阶段 D：灰度前 A/B 安全实验

* 小流量
* 强监控
* 实时失败率

## 3️⃣ 字节系一句话总结

> **“不是防住 100%，而是让失败不可规模化。”**

# 三、OpenAI 风格（模型级 + 系统级）流程

> 关键词：**模型能力边界、系统性风险、不可恢复失败**

## 1️⃣ OpenAI 的核心假设

> **“单点失败不可怕，不可恢复失败才可怕。”**

所以他们极度关注：

* 可复制性
* 系统级风险
* 长期滥用路径

---

## 2️⃣ 内部常见流程（公开信息 + 业界共识抽象）

### 阶段 A：能力解锁评估（Capability Unlock）

* 新模型是否：

  * 更会说服？
  * 更会写代码？
  * 更容易被越狱？

📌 有些能力：

> **即使“效果很好”，也会被压制**

---

### 阶段 B：Threat Modeling（威胁建模）

* 谁是攻击者？
* 攻击目标是什么？
* 最坏后果是什么？

这一步**不是跑工具，而是写文档**

---

### 阶段 C：红队（含外部）

* 内部红队
* 学术合作
* 外部专家

目标：

> **找“他们没想到的风险”**

---

### 阶段 D：系统级 Guardrail 验证

不是只测模型，而是：

* 模型
* policy
* tool
* 日志
* 响应策略

## 3️⃣ OpenAI 风格一句话

# 四、给你一套「可直接复刻」的统一流程（企业落地版）

如果你现在在企业内部，我建议你直接用这个 **7 步版**：

```text
1. 安全基线 + 回归（Gate 0）
2. 自动红队（Gate 1）
3. 业务场景专项（Gate 2）
4. Agent / Tool 越权测试（Gate 3）
5. LLM-as-Judge + 人工复审（Gate 4）
6. 放行评审（Go / No-Go）
7. 上线灰度 + 强监控
```

### 放行标准（强烈建议你照抄）

| 项目        | 要求  |
| --------- | --- |
| 严重违规      | 0   |
| 可复现越狱     | 0   |
| Agent 越权  | 0   |
| 安全回退      | 不允许 |
| 人工 Review | 已完成 |
