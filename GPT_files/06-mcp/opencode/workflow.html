MCP Scanner 工作流与后 15 个漏洞检测可视化

本页面用于理解项目如何通过 Agent 选择目标、生成检测请求、执行 MCP 交互、收集证据、判定漏洞，并解释什么情况下会跳过检测。

一、整体扫描链路

1. 请求解析/mcp-scan 输入 target、profile、auth、callback、source、log 等。
2. 安全边界检查目标 URL、私网/HTTP 开关、payload、第三方 URL、调用预算。
3. 能力发现连接 MCP server，枚举 tools、resources、resource templates、prompts、server instructions。
4. 漏洞选择根据 profile 和 --vuln 选择 MCP-XXX 定义、prompt spec、validator。
5. Agent 规划active/stateful/concurrent 类调用 Agent 选择候选接口并生成 TestPlan。
6. 执行判定执行 call_tool/read_resource/get_prompt/relist，Validator 用证据给出 verdict。

二、Agent 相关执行流程

selectApplicability

Agent 根据漏洞定义、prompt spec、capability snapshot 选择候选 tool/resource/prompt/server。

generateTestPlan

Agent 为候选目标生成 baseline 与 testCases，每个 case 含 operation、target、input、risk、预期观察点。

Policy Gate

执行前检查漏洞是否启用、risk 是否允许、payload 是否破坏性、URL 是否只指向 callback、是否超预算。

executeOperation

按 operation 映射到 MCP：call_tool、read_resource、get_prompt、relist_capabilities。

Validator

最终漏洞状态不让 Agent 自证，而由 validator 使用 evidence、snapshot、callback hits、auth probe、log/source 判定。

三、跳过检测的常见原因

类型可能原因你需要提供什么
前置条件缺失漏洞需要 callbackUrl、sourcePath、secondaryAuthEnv、authEnv、logPath，但请求未配置。加 --callback-url、--source-path、--secondary-auth-env、--auth-env、--log-path。
不适用Agent 没找到相关候选接口，比如没有文件工具、没有数据库查询工具。确认目标 MCP 暴露了对应 tool/resource/prompt。
策略拒绝intrusive case 未允许、payload 破坏性、URL 不是 callback、payload 太大、调用预算耗尽。选择合适 profile，必要时加 --allow-intrusive，配置 callback，调大预算。
证据不足没有成功响应、超时、协议错误、relist/log/callback/auth probe 不可用。检查目标稳定性、超时、网络、日志路径、callback 可达性。
主动取消/超时AbortSignal 或漏洞级 timeout 触发。延长 timeout 或减少并发/目标数量。
